Dynamics 365 Cloud / Power Apps URI Security Testing Coverage
Scope: Dynamics 365 online / Dataverse / Power Apps / Power Platform admin surfaces.
Purpose: Access-control and configuration testing coverage for low-privileged users, business users, developers, admins, disabled users, guest/external users, and app-only/service principals.

Important accuracy note:
- The Dataverse Web API, XRMServices, and Power Platform provider/API patterns below are documented platform surfaces.
- Classic web-client ASPX paths such as /main.aspx, /tools/*, /biz/*, /_common/*, /_controls/*, /Activities/*, /SFA/*, /CRMReports/*, and /WebResources/* are known Dynamics CRM / Dynamics 365 route families that may exist, redirect, or return 403/404 depending on tenant, module, app, Unified Interface rollout, and environment configuration.
- Replace placeholders like {org}, {environmentId}, {recordId}, {entityLogicalName}, {solutionId}, {appId}, {flowId}, {userId}, {roleId}, {teamId}, {businessUnitId}, {webResourceName}, {connectorName}, {customEntity}, {tenantId}, and {guid}.
- Test all methods where applicable: GET, POST, PATCH, PUT, DELETE. Access should be validated by privilege outcome, not just HTTP response code.

22. TESTING NOTES TO APPLY TO EVERY URI
================================================================================
- Test unauthenticated access.
- Test authenticated low-privileged internal user.
- Test authenticated low-privileged external/guest user if supported.
- Test disabled user/session reuse.
- Test user from another business unit.
- Test user with app access but no admin role.
- Test user with maker/developer permissions but no admin role.
- Test app-only/service-principal access.
- Test GET/list/read.
- Test POST/create.
- Test PATCH/update.
- Test DELETE/remove.
- Test $select sensitive fields.
- Test $filter enumeration.
- Test $expand relationship disclosure.
- Test FetchXML query behavior.
- Test $batch behavior.
- Test direct deep link bypass of UI navigation.
- Test object-level access by changing {recordId}.
- Test cross-business-unit data exposure.
- Test share/team inherited access.
- Test file upload/download execution risk.
- Test external URL insertion in SharePoint/document locations.
- Test email, alert, campaign, and agency-wide communication abuse.
- Confirm Deny/403 where the user has no business need.
- Confirm access is controlled by Dataverse security roles, table privileges, field security, app sharing, DLP policies, environment roles, Power Platform admin settings, and SharePoint permissions where applicable.
